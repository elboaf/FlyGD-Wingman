## 3. Version support is not permission

Capability vocabulary remains `shared-source-v1` plus explicitly approved `combat-v2`, unique and canonically shared-first. `combat-v2` requires the shared capability. These are rights, not selectable old/new wire formats. Let `D` be device approvals, `C` the immutable session ceiling, and `K` explicit session acknowledgement.

| Operation | Required authority rule |
| --- | --- |
| Device response | Return each complete validated array independently; never substitute `D` for `C` or `K`. No vocabulary intersections for old clients. |
| Pairing upgrade | Browser explicitly approves incoming DPS, activity, NEUT and tackle labels. Same-key completion may union those rights into `D`; new `C` is only this request's approved scope. Initial `K=[]`. |
| Acknowledge | Unique requested rights must lie within both `D` and `C`; route support or saved metadata cannot create approval. |
| Renewal/recovery | Renewal preserves `C` and existing acknowledgement semantics. Recovery creates `C=D`, initial `K=[]`, without broadening durable `D`; recovery cannot invent combat or automatic approval. |
| Combat PUT | Require both rights in `D∩C∩K`, participation, feature activation and all existing fresh source/session/link/participation proofs. Withdrawal retains its applicable admission rules. |
| Combat GET | Existing authorized shared-read admission remains mandatory; combat approval is publisher disclosure consent, not new receiving permission. Recheck publisher approval and row provenance before disclosure; never broaden fleet scope. |

Automatic approval is independent: existing shared-source device/session/acknowledgement permission plus a distinct explicit signed persistent-consent action. An automatic-only boss needs no combat approval and may have telemetry participation Off. Pairing, Fleet Read grants, historical Start, combat approval and previous session acknowledgement do not imply automatic intent. Migration adds neither new right nor persistent opt-in.

### Updated automatic Off/Stop — decided behavior, separate API-detail owner

- Retain immutable automatic/manual source provenance and automatic sources' owning consent ID/`consentGeneration`. Keep `sourceGeneration` distinct; a future fleet/source never rebinds an old source to newer consent.
- Authorized source Stop checks its source generation and resolves the immutable consent binding. If that consent generation is current, atomically disable it, fence queued/in-flight reconciliation and stop its automatic sources—even if the target naturally ended before Stop arrived.
- Consent-aware Off checks current consent generation/revision. Re-enable creates a new generation. Delayed/repeated Stop for an older generation may settle that old source but cannot disable newer consent or its sources; never rebase an old opt-out over a new opt-in.
- Unknown/purged source IDs cannot disable current automation. Manual-source Stop remains source-specific. Revocation of the approving device fences its consent; another device needs explicit reauthorization, not silent consent transfer. Global disable overrides all work.
- Updated clients settle explicit Off/Stop and converge cross-device status; an ended-source GET is not consent-off acknowledgement. GET remains read-only. There is no outstanding old-client Stop decision; the exact control/receipt DTOs and retention rules are closed in the automatic annex and await independent review.

### 4.2 Width, cardinality and serialization — one coherent bound

- Keep **32 PUT rows** and existing **8,192 GET-row outer bound**. A `fleet-shared-admission.ts:35–220` already bounds the *entire admission expansion* at 8,192 items and refuses overflow atomically. Do not reduce authorized scope or add paging/roster interfaces. Actual successful authorization usually permits fewer than the conservative 8,192-row serialization envelope; this proof does not claim a real 8,192-row admission transaction exists.
- **PUT bound = 524,288 bytes (512 KiB)** on actual raw UTF-8 bytes before parsing/signature service entry; service checks the validated whole-envelope serialized bytes again. Preserve `_json`'s actual Python default `json.dumps(value).encode("utf-8")` for this operation: ASCII escaping, default spaces, finite integers/null only. Maximum legal 32-row envelope is **419,900 bytes**, versus 154,744 compact/unescaped bytes. Compact UTF-8 is not the size of today's signed client bytes. Sign the exact bytes that are sent. Whitespace/padding is not permission to exceed the raw bound; duplicate keys/nonfinite numbers/extensions remain invalid.
- **Canonical GET bound = 67,108,864 bytes (64 MiB)** in route output and W snapshot client read(bound+1), before JSON parsing; the operation-specific v2 table in `fleet-telemetry-v2-api-contract.md` is authoritative for all response bounds. Its non-snapshot increases are intentional v2 client/server changes, not current W behavior (currently every response except snapshot GET uses a 64KiB reader). Canonical output is ordinary compact `JSON.stringify` encoded UTF-8, no pretty-printing, ASCII-only recoder, HTML escaping or intermediary reserialization. Use identity HTTP content encoding, or separately enforce this same bound on the fully decoded entity; a compressed-byte-only limit is insufficient. Request binding/no-store still apply before acceptance.
- Maximum legal compact row widths are **4,833 PUT / 5,739 GET bytes**. The GET figure includes a 200-scalar supplementary character name, all 16 maximum names, three null buckets, maximum-width IDs/ages/DPS, `stale` and a 36-character lowercase UUID. A maximum envelope of 8,192 distinct IDs/UUIDs is **47,022,137 bytes**, well below 64 MiB. The proof executes W's actual `_json` function in isolation and native Node `JSON.stringify` on the full maximum response and compares bytes/hash. UTF-8 supplementary scalars dominate allowed quote/backslash escapes; ASCII-escaped PUT uses 12 bytes per supplementary scalar. Arbitrarily escaped/noncanonical GET bytes are not a required successful server representation.

A server oversize/invalid output fails as a closed whole operation; never return a subset, clamp names, or pad with unavailable/zero rows. The expanded 64-MiB ceiling is a worst-case parsing/allocation budget, not a claimed normal response size; actual memory/performance acceptance remains an implementation gate.

## 5. Pinned event order and original measurement freshness

### 5.1 Clock domain and finite assumptions

All DB times are integer milliseconds from **one post-lock `clock_timestamp()` sample** for authority and age admission; not application time or transaction-start time. Local x/m/r/s below are monotonic seconds. Internally compare exact ratios of the supplied binary float values (e.g. `as_integer_ratio`), and floor the final conversion once; do not round each deadline to milliseconds before ordering or use an epsilon that aliases distinct accepted IDs.

An authenticated request-bound DB anchor is `(T,r)`, with receipt r measured after the full response. It may be used only with request elapsed ≤5,000ms and age `0 ≤ s-r ≤60,000ms`. Timeouts/body completion over five seconds provide no anchor. Use the existing serialized signed lane for fresh device/snapshot anchors, never a new heartbeat/clock worker.

**Supported clock contract:** DB integer time is nondecreasing and all participants' suspend-inclusive monotonic elapsed clocks differ from DB elapsed by at most **100ms over any involved interval ≤95 seconds** (60-second anchor age + 30-second event lookback + five-second response). This bound includes timestamp quantization, drift, failover skew and elapsed sampling error. Use **200ms safety margin** on new mappings and receiver projections below. This is an explicit operational precondition, not a claim that `clock_timestamp()` alone enforces it. A failover/slew is supported only inside these bounds. Operators must close/fence admission on known steps or failover outside them; undetected arbitrary DB jumps cannot be proved safe by an RTT heuristic.

On suspend/resume or unsupported/reset/paused elapsed time, fence pending samples/evidence, reacquire an anchor and follow the lost-continuity rule below; do not add wall-clock fallback. Local platforms must provide verified suspend-inclusive elapsed time, or reliably report suspend **before** any resumed publication. A missing signal on a paused monotonic clock is unsupported. Cross-anchor feasible-offset intervals (DB sample lies between request start and receipt, expanded by the 100ms bound) must intersect; nonintersection fences continuity. Intersection is necessary, not proof against arbitrary hidden clock faults. Deployment/Windows verification must establish this platform contract before activation.

### 5.2 Order-preserving origin insertion (C-owned, outside replaceable workers)

One retained C owner per `(relay origin/account identity, coherent DB domain, local elapsed lifetime)` stores time points and associations for only staged publication candidates; no metrics-side map, persistence, raw log or new worker. I injects this owner through existing composition, independent of replaceable sharing workers/sessions. Authority revocation still fences use immediately.

For each unexpired row/observation use immutable local event coordinate **`x = deadline - 30s`**, immutable key `(character_id, telemetry lifetime token, row-or-kind/name slot, accepted ObservationId)` and original deadline. A changed deadline for an existing key is invalid. The local model guarantees row x ≥ every effect x; validate this handoff, not a guessed event sequence. For a numeric snapshot use coordinate **`m = FleetSnapshot.sampled_at_mono`** and key `(telemetry activation/elapsed lifetime, exact m)`; keep its immutable aggregate values. Same m with conflicting measured payload is invalid. No new wire identity is introduced.

At one paced staging attempt, prune expired associations, take a detached candidate copy and collect all new event/sample coordinates. Process new coordinates in ascending exact order; ties share one origin, independent of slot, identity or insertion order. For each x:

```text
C(x) = T + floor(1000 * (x-r)) - 200
L(x) = max({ O_i : retained x_i <= x } union {0})
U(x) = min({ O_i : retained x_i >= x } union {JS_SAFE_MAX})
O(x) = min(U(x), max(L(x), C(x)))
```

Existing associations always return their original O. `L>U`, nonfinite time, negative candidate, out-of-range origin, conflicting immutable value or invalid sample ordering suspends the **whole replacement** (`None`), with no partial rows/uncertain empty publication. Capacity reservation and all insertions commit atomically before signed preparation; abandoned/attempted candidates retain their pins. Never repin a survivor to make the batch valid. An origin may be *older* than a new event's latest anchor estimate; this conservatively shortens remote visibility and cannot invent activity.

**Proof:** induction gives nondecreasing O for all retained x: insertion lies between every predecessor/successor; equal x has L=U. Since row x≥effect x, `S-O_row ≤ S-O_effect` for any shared sample S. A new ID with later x may get equal O after a worse anchor (early expiry), never a smaller O; same-timestamp facts retain equal O. A delayed older event is bounded above by already pinned newer evidence, even under a better anchor. No pin changes. Conservatism: C(x)≤DB(x)−100ms under §5.1. An inherited lower bound also satisfies this because DB is nondecreasing; an upper bound only decreases C/L. Thus O+30s cannot exceed the original local deadline in the supported elapsed model. The same argument bounds measurement S+10s by original m+10s. If no legal live batch remains, suspend rather than trying to “repair” ordering through per-row omission.

### 5.3 Sampling is provenance, not serialization time

1. Admit a snapshot only with finite m and **`0 ≤ 1000*(now-m) < 5000`**, evaluated from `sampled_at_mono`, never submit/queue time. Preserve m and measured nullable DPS through projection and queued work. The pure combat reader can prune observations; it cannot recalculate the exported ten-second aggregate or change m. A fresh metrics-produced snapshot may have identical numbers and a genuinely newer m.
2. Pin **`S = O(m)`** once using §5.2, with all row/effect coordinates ≤m. `sampled_at_ms=S`, never an estimate at serialization/send time. Same m/aggregate republished with new UUID, new worker/session or a better anchor retains S. New m alone permits fresher numeric transport; event origins remain unchanged. Encode `activity_age_ms=S-O_row` and each observation age `S-O_effect`. This is age **at original measurement**, not age at serialization; the relay adds transit/queue age exactly once.
3. **Final pre-send gate**, after key unwrapping/journal/signature preparation and immediately before handing the immutable bytes to HTTP: recheck original m age (<5s), activation/authority/continuity fences, locally unexpired rows, anchor lifetime and all submitted dimensions/origins. If this fails, send nothing; an already journaled attempted revision remains consumed under existing rules. Do not rewrite signed bytes to a new S or partially replace a row set. Next paced attempt uses a newly selected genuine metrics snapshot. Subsequent network/lock delay is bounded by the relay's sample check.
4. At post-lock DB N, nonempty PUT requires `0 ≤ N-S <10000`. For every row require `N-O_row <30000` and nonnegative ages; any expired submitted row rejects the atomic replacement. Effective combat age is `(S-O)+(N-S)=N-O`. Effects expiring in queue/transit/residence are naturally pruned; empty effect arrays disappear. Never fabricate numeric zero from unavailable metrics. Explicit withdrawal is exactly `{protocol:2,sampled_at_ms:0,rows:[]}` and bypasses sample-age validation only, never authority.
5. Persist original S/O, provenance and fresh publication UUID atomically. Transport live iff `N-S<3000`, expires at S+10000, independently bounded by authority/lease expiry. GET post-lock R returns age `R-S`, activity/effects `R-O`, pruning expired rows/effects. An unchanged cached measurement cannot gain live time through republishing; a fresh healthy metrics sample legitimately supplies zero/zero during quiet hold.

### 5.4 Retention, recovery and receiver projection

- **Publisher capacity/lifetime:** at most `32*(1+19)+1 =641` new association keys per paced staging attempt, with starts ≥500ms apart across worker/session replacement. Do not allocate pins on arbitrary telemetry submission or every scheduler scan. Keep row/effect keys until their *original* local deadline (≤30s from x), sample keys until m+10s; shared time points until their last associated horizon. Even pruned/replaced slots retain their old pin until that horizon, because a still-admissible older snapshot can recur. Upper bound `(floor(30000/500)+1)*641 =39,101` associations and no more time points. Preflight reservations above this cap suspend without eviction. Retain the staging cadence deadline with the owner; replacement may not bypass it. No lifetime grows on retries.
- **Same-identity worker/session recovery:** retain this owner, measurement pins, event pins and cadence floor; drop/reacquire the anchor as appropriate. Transport recovery is not model/source invalidation. Genuine model source/session replacement rotates the existing local lifetime token and clears local observations; delayed queued old snapshots remain fenced by activation/source admission. Do not ask M to issue new IDs for cached observations.
- **Lost/impossible continuity:** record a fresh local cutoff F, invalidate pending work/anchor, and suspend any candidate containing unexpired event coordinate x≤F or a sample m≤F. Accepted-ID novelty alone is insufficient: a delayed older event received after F remains pre-fence. A genuinely later row ID may publish only when *all dependent surviving effect evidence* is post-fence; otherwise the whole replacement waits. After at most 30 seconds of trustworthy elapsed time old evidence naturally expires. Full process restart discards old model observations; absent trustworthy elapsed continuity, require that discard/fresh model lifetime instead of a guessed wait. Reacquire permission separately; nothing infers consent.
- **Receiver: bounded origin-scoped GET intervals, not a global low-water offset.** For each wholly validated, request-bound GET i with post-lock DB `R_i`, full elapsed `0≤e_i≤5s` and receipt `q_i`, retain one `(R_i,B_i)` where `B_i=q_i-e_i-R_i/1000-0.200`. This protects event origins in `(R_i−30000,R_i]` and measurement origins in `(R_i−10000,R_i]`; open lower ends match the wire's strict hard-expiry inequalities. It stores no character/name/observation keys or histories. Retain the last accepted R and the existing GET request-start cadence floor with this owner through payload clears and same-domain worker/session recovery. No new network/timer owner.
- **Atomic admission/pruning:** validate the whole closed payload, binding, clock assumptions, elapsed bound, original returned ages and `R≥last_R`; require GET request starts ≥500ms apart, retaining this existing cadence across owner replacement. On malformed/regressing R, invalid time or exhausted capacity, reject the *whole response* without changing rows, intervals, last_R or their protections. The signed lane still records the actual attempted-request pacing; a refused response never releases its request slot. On a detached candidate, remove old records **only when new authenticated R satisfies `R−R_i≥30000`**, then append the new record, check capacity and compute the complete projection before commit. Do not prune from local time, display expiry, empty responses or a horizon renewed by unrelated GETs. Equality of R is not by itself regression, but still has to pass the coherent-clock/cadence checks. Receiver R regression fences shared work for clock diagnosis; never reset history and accept that response as a fresh clock domain.
- For each valid current origin x and lifetime `L=30000` (row/effect) or `10000` (numeric sample), use **`B_L(x)=min{B_i : R_i−L < x ≤ R_i}`**. The newly admitted GET covers every valid returned origin, so the set cannot be empty. Derive combat deadline `x/1000+B_L(x)+30` and numeric transport origin `S/1000+B_10000(S)`; classify via existing three/ten-second freshness. UUID changes never enter the lookup. Cache these projected values with the current payload for normal local redraw; no scan belongs on every frame.
- **Non-renewal and order proof:** if x was protected by record i and is still legal at a later accepted R, i cannot have been pruned: `R−R_i≥L` with `x≤R_i` would imply `R−x≥L`, making x hard-expired. Further covering records only lower the minimum; clearing/replaying/recovering cannot increase a surviving old O/S deadline. For all currently legal x, `x>R−L≥R_i−L`, so covering records are exactly the suffix with `R_i≥x`. Older x have supersets of newer x's covering records; therefore both `B_L(x)` and `x/1000+B_L(x)` are nondecreasing. Row/effect order remains intact, not merely the wire-age invariant. Once R proves an old interval dead, no legal old origin can resurrect after its removal.
- **Recovery of genuinely new freshness:** a bad GET cannot bias any later origin `x>R_bad`, even while an older effect/sample still survives. Healthy GETs then project genuinely new measurement origins using healthy offsets; they do not extend the bad interval to cover future origins. Counterexample to the rejected global scheme: one GET with `R=104800ms,q=4.8s,e=4.8s` pins `B=−105s`; every subsequent healthy GET (`R=100000+1000q`, `e=20ms`) with fresh `S=R−200ms` forever appears **5,200ms old/stale** under a global minimum. Under these intervals, at `q=5.5s,R=105500ms`, fresh `S=105300ms` appears **420ms old/live**, while old `S=104600ms` and effect `O=104000ms` retain their earlier protections. A 120-second continuous-update proof exercises this; no quiet interval/reset is required.
- **Finite capacity/performance:** retained records have DB sample times in `(R−30000,R]`. §5.1 bounds their local sample-time span by 30,100ms; each request starts no more than 5,000ms before its sample. With ≥500ms request-start spacing, a conservative maximum is **`floor((30000+100+5000)/500)+1 =71 records`**, derived from the unchanged profile. There is one current-domain ring/list, not 71 per row or origin. Sorted endpoints plus suffix minima give O(71) preprocessing per response and O(log 71) lookup per returned origin, without any per-observation history. Payload remains bounded by the existing 8,192-row/19-observation limits. The ordinary actual-attempt cadence floor must survive failures/replacement as well as successful responses; a cadence violation or capacity overflow suspends instead of evicting a protected record.
- **Clear, continuity and residual UX:** payload clear/hydration retains intervals; same-domain session recovery reinjects them. No GET means no pruning work; the fixed-size records can stay idle while payload expires naturally. If receiver timing continuity is truly lost, discard payload and fail closed; record one first new valid authenticated R₀ as a recovery barrier and suspend whole snapshot projections until a subsequent valid R≥R₀+30000 proves all pre-reset origins dead. R₀ is fixed, never extended by intervening GETs; those responses cannot reset the barrier. This exceptional lost-history path costs up to thirty seconds of DB advance before fresh projection, unlike ordinary clear/session recovery which retains intervals and has no such delay. A different DB domain discards old payload/history only behind an explicit identity/domain fence, never merely a session change. The receiver may still show an old measurement stale or hide an old effect early because its actual conservative bound is preserved; it cannot repair that uncertainty. A newly received sample whose pinned S is still ≤R_bad may temporarily share the bad offset, but this ends when genuinely newer origins pass R_bad—there is **no fleet-wide permanent stale state under recovered network/anchors**. The publisher's separate need for a fresh usable anchor remains unchanged. Real large-response allocation/latency and Windows clock/suspend support are still implementation gates, not excuses to accept permanent staleness.
